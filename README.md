# ESPReL MRA v2 — ระบบตรวจประเมินความปลอดภัยห้องปฏิบัติการ มหาวิทยาลัยนเรศวร

Web application (Python/Flask) · ฐานข้อมูล **Supabase (Postgres + Storage)** · deploy บน **Vercel** · CI/CD ผ่าน **Git (GitHub Actions)** · เข้าสู่ระบบด้วย **LDAP มหาวิทยาลัย**

## ขั้นตอนการทำงาน

```
ห้องปฏิบัติการกรอกใบสมัคร FM-001 ที่ /apply (ไม่ต้องมีบัญชี) → ระบบสร้างบัญชีห้อง + ส่งอีเมลชื่อผู้ใช้/รหัสผ่าน
→ เข้าสู่ระบบ พิมพ์ใบสมัครให้ผู้มีอำนาจลงนาม แนบกลับ → หัวหน้าผู้ตรวจอนุมัติ → ระบบเสนอทีมผู้ตรวจอัตโนมัติ → สร้างการตรวจ
→ ตรวจรอบ 1 (ให้คะแนน, NC/OBS, ถ่ายรูปหลักฐาน) → ประชุมปิด → ออก Report 1 (PDF/Word)
→ ห้องปฏิบัติการเห็นผลทุกข้อ + ตอบ CAPA ทุกข้อ NC/OBS พร้อมหลักฐาน → กด “ส่ง CAPA”
→ หัวหน้าผู้ตรวจเริ่มรอบ 2 (ตรวจเฉพาะข้อ NC/OBS, ข้ออื่นล็อกคะแนนรอบ 1) → ออก Report 2
```

| บทบาท | ทำอะไรได้ |
|---|---|
| ผู้ดูแลระบบ (admin) | ทุกอย่าง + จัดการผู้ใช้/ตั้งค่า |
| หัวหน้าผู้ตรวจ (lead) | อนุมัติใบสมัคร, จัดทีม, สร้างรายงาน, เริ่มรอบ 2, ส่ง CAPA กลับ, เปิดแก้ไขรอบ |
| ผู้ตรวจ (assessor) | ให้คะแนน, บันทึก NC/OBS/ข้อเสนอแนะ, แนบรูป, สรุปประชุมปิด |
| ห้องปฏิบัติการ (lab) | เห็น**เฉพาะห้องของตนเอง**: สถานะใบสมัคร, ผลการตรวจทุกข้อ (หลังออก Report 1), ตอบ CAPA + แนบหลักฐาน, ดาวน์โหลดรายงาน |

**การเข้าสู่ระบบ**
- ผู้ตรวจ/หัวหน้าผู้ตรวจ/ทีมงาน: LDAP ของมหาวิทยาลัย — admin ต้องเพิ่มชื่อผู้ใช้ LDAP ไว้ที่เมนู “ผู้ใช้” ก่อน (ผู้ที่ไม่อยู่ในรายชื่อเข้าไม่ได้)
- ห้องปฏิบัติการ: **อีเมลผู้ประสานงาน (ข้อ 13 ในใบสมัคร) + รหัสผ่านที่ระบบสร้างและส่งทางอีเมล** · เข้าครั้งแรกต้องตั้งรหัสใหม่ ·
  ลืมรหัส → “ลืมรหัสผ่าน?” (ส่งลิงก์ใช้ได้ครั้งเดียว 24 ชม.) · admin/หัวหน้าผู้ตรวจกด “ส่งรหัสผ่านใหม่ทางอีเมล” ได้ที่เมนู “ผู้ใช้”
- อีเมลเดิมสมัครห้องที่ 2 → ห้องใหม่เพิ่มในบัญชีเดิม (ไม่สร้างรหัสใหม่) · ใบสมัครสาธารณะสร้างห้องใหม่เสมอ ไม่ผูกกับห้องเดิมจากข้อมูลที่กรอก
  (กันการอ้างชื่อห้องผู้อื่นเพื่อดูผลการตรวจ) — ห้องที่มีอยู่แล้วจากการนำเข้า ให้หัวหน้าผู้ตรวจผูกบัญชีที่หน้า “แก้ไขข้อมูล/ทีม”

## 1) ตั้งค่า Supabase
1. สร้าง Project ใหม่ (Region: Singapore)
2. **SQL Editor** → วางไฟล์ `supabase/migrations/0001_init.sql` แล้ว Run (สร้างตาราง, เปิด RLS ปิดการเข้าถึงผ่าน API, สร้าง bucket `esprel` แบบ private)
   - ฐานข้อมูลที่สร้างจากเวอร์ชันก่อน: Run `0002_fm001_application.sql`, `0003_lab_accounts_email.sql`, `0004_application_review.sql` และ `0005_assessor_registry.sql` เพิ่ม — หรือปล่อยให้แอปเพิ่มเองเมื่อ `AUTO_MIGRATE=1`
3. คัดลอกค่า
   - Project Settings → Database → Connection string → **Transaction pooler (port 6543)** → `DATABASE_URL`
   - Project Settings → API → Project URL → `SUPABASE_URL`, `service_role` key → `SUPABASE_SERVICE_ROLE_KEY` (ห้ามเปิดเผย)

## 2) Git + Vercel (CI/CD)
1. สร้าง repository บน GitHub แล้ว push โค้ดนี้ (`git remote add origin … && git push -u origin main`)
2. Vercel → **Add New Project** → Import repo นี้ → เลือกแถว **app (Flask)** → *Import single project* (ไม่ต้อง deploy `ldap_gateway`) — Vercel ใช้ `app.py` เป็น entry, `vercel.json` กำหนด region โตเกียว (hnd1) ใกล้ Supabase
3. Vercel → Settings → **Environment Variables** ใส่ค่าตาม `.env.example`
   (`SECRET_KEY`, `DATABASE_URL`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `LDAP_*`, `SMTP_*`, `MAIL_FROM`, `APP_BASE_URL`, `ADMIN_INITIAL_PASSWORD`)
4. ทุกครั้งที่ push → GitHub Actions รันทดสอบ (SQLite + Postgres) และ Vercel สร้าง Preview; merge เข้า `main` → Production
5. ตั้ง Branch protection ให้ `main` ต้องผ่าน CI ก่อน merge
6. เปิด `https://<โดเมน>/healthz` ควรได้ `{"db":"postgres","storage":"supabase","ldap":true,...}`
7. เข้าสู่ระบบด้วย `admin` / `ADMIN_INITIAL_PASSWORD` → เพิ่มผู้ตรวจ (ชื่อผู้ใช้ LDAP) → ตั้งค่า `ALLOW_LOCAL_LOGIN=0` หลังมีผู้ดูแลที่เป็น LDAP แล้ว

## 3) อีเมล (SMTP) — จำเป็นสำหรับส่งรหัสผ่านให้ห้องปฏิบัติการ
- ขอบัญชีอีเมลหน่วยงานสำหรับส่งอัตโนมัติ (เช่น esprel@nu.ac.th) จากกองเทคโนโลยีสารสนเทศ แล้วใส่ `SMTP_*`, `MAIL_FROM`, `APP_BASE_URL` ใน Vercel
- ยังไม่ตั้งค่า SMTP + รันในเครื่อง → โหมดทดสอบ: แสดงรหัสผ่าน/ลิงก์บนหน้าจอแทนการส่งอีเมล · บน Vercel ที่ยังไม่ตั้งค่า จะไม่แสดงรหัส (admin ส่งใหม่ได้ภายหลัง)
- ประวัติการส่ง (ไม่เก็บเนื้อหา/รหัสผ่าน) อยู่ในตาราง `mail_log` · ผู้ส่งใบสมัครใหม่แจ้งเตือนหัวหน้าผู้ตรวจที่มีอีเมลในระบบ
- ใบสมัครสาธารณะมีกันสแปม (honeypot + จำกัด `PUBLIC_APPLY_PER_HOUR` ครั้ง/ชม./IP)

## 4) LDAP มหาวิทยาลัย — ยืนยันที่เซิร์ฟเวอร์ภายในก่อน แล้วจึงตรวจผู้ใช้ใน Supabase
```
ผู้ตรวจกรอกบัญชี NU → ESPReL ส่งไป LDAP gateway บนเซิร์ฟเวอร์ภายใน มน. (bind user@nu.local แบบระบบ NRED)
  ผ่าน → ตรวจตาราง users ใน Supabase: มี → เข้าได้ตามบทบาท
                                   ไม่มี แต่อยู่ใน “ทะเบียนผู้ตรวจ” (อีเมล @nu.ac.th ตรงกัน) → เปิดบัญชีผู้ตรวจอัตโนมัติ
                                   ไม่มีทั้งคู่ → ปฏิเสธ
  ไม่ผ่าน → แจ้งรหัสผ่านไม่ถูกต้อง (จำกัดผิด 10 ครั้ง/15 นาที)
```
- ติดตั้ง API ใน NRED: `python ldap_gateway/install_into_nred.py` ในโฟลเดอร์ NRED — คำขอ/คำตอบลงลายเซ็น HMAC, กัน replay, HTTPS เท่านั้น (ดู `ldap_gateway/README.md`)
- แอปบน Vercel ตั้ง `LDAP_GATEWAY_URL` + `LDAP_GATEWAY_KEY` · ถ้าติดตั้งแอปในเครือข่าย มน. ใช้ `LDAP_URL=ldap://10.10.10.71` + `LDAP_UPN_SUFFIX=@nu.local` แทน
- พิมพ์ได้ทั้ง `gitsadap`, `gitsadap@nu.ac.th`, `NU\gitsadap` · รหัสผ่านว่างถูกปฏิเสธทุกครั้ง · บัญชีรหัสผ่านภายใน (admin/ห้องปฏิบัติการ/ผู้ตรวจภายนอก) ไม่ผ่าน LDAP
- `/healthz` แสดง `"ldap": "gateway"` หรือ `"direct"`

## ใบสมัคร FM-001 (Rev.08)
- `/apply` (ลิงก์ “สมัครรับการตรวจประเมิน” ที่หน้าเข้าสู่ระบบ) — ทุกคนกรอกได้โดยไม่ต้องมีบัญชี; ห้องที่มีบัญชีแล้วใช้เมนู “สมัครรับการตรวจ (FM-001)” (บันทึกร่างได้)
- ฟอร์มเว็บตามแบบฟอร์มกระดาษครบทุกข้อ (1–13, คำรับรอง, ผู้มีอำนาจลงนาม)
- ข้อ 1–7 บันทึกเป็นข้อมูลห้องปฏิบัติการ (ครั้งถัดไปดึงมาเติมให้อัตโนมัติ) · คะแนนรวมข้อ 12 คำนวณให้
- กด “ส่งใบสมัคร” ระบบตรวจความครบถ้วน + ต้องแนบผลการสำรวจ ESPReL Checklist จากระบบ วช. → ได้เลขที่ใบสมัครอัตโนมัติ `001/ปี` (หัวหน้าผู้ตรวจแก้ได้)
- “พิมพ์ใบสมัคร FM-001” = เอกสาร A4 2 หน้า หน้าตาเหมือนต้นฉบับ (โลโก้ วช./มน./ESPReL NU, QR 3 จุด, กรอบติดต่อสีเหลือง) → ลงนาม → แนบไฟล์ที่ลงนามกลับ
- หน้า “ใบสมัคร & จัดทีม” แสดงเลขที่ ลิงก์ใบสมัคร และสถานะไฟล์แนบ (ผลสำรวจ/ฉบับลงนาม) · ใบสมัครที่ยังเป็นร่างไม่แสดง · อนุมัติแล้วห้องแก้ไขไม่ได้
- **ไม่อนุมัติ / ส่งกลับ** (รายใบสมัคร) ต้องระบุเหตุผล (มีข้อความสำเร็จรูปให้เลือก) → ห้องเห็นเหตุผลในระบบ + ได้รับอีเมล → แก้ไข/แนบเอกสารแล้ว “ส่งใบสมัครอีกครั้ง” → กลับมารออนุมัติ (แสดง “ส่งใหม่หลังแก้ไข”)
- อนุมัติแล้วระบบส่งอีเมลแจ้งห้องปฏิบัติการ · ประวัติการส่งกลับ/ส่งใหม่บันทึกใน audit_log
- ข้อความกรอบเหลือง (ผู้รับ/กำหนดส่ง/เบอร์ติดต่อ) และรหัสฉบับแบบฟอร์ม แก้ได้ที่เมนู “ตั้งค่า”

## ทะเบียนผู้ตรวจประเมิน (เมนู “ผู้ตรวจ”)
- นำเข้ารายชื่อผู้อบรมจาก Excel (หัวตาราง: รายชื่อ · สังกัด · อีเมล์ · เบอร์โทรศัพท์ · ESPReL · Peer) — อ่านทุกชีต รวมรายชื่อซ้ำ แยก มน./ภายนอก
  ปีที่อบรมอ่านจากหัวเรื่อง/ชื่อชีต/ชื่อไฟล์ · นำเข้าซ้ำได้ (ไม่ทับข้อมูลที่แก้ในระบบ) · แจ้งเตือนอีเมลภายนอกของบุคลากร มน./ไม่มีอีเมล
- ประวัติการอบรม (ESPReL / Peer + ปี) และประวัติการตรวจของแต่ละคน
- “เปิดสิทธิ์เข้าระบบ”: อีเมล @nu.ac.th → บัญชี NU (LDAP) · อีเมลภายนอก → อีเมล + รหัสผ่านที่ระบบสร้าง (ส่งทางอีเมล) · บทบาทเริ่มต้นผู้ตรวจประเมิน
- หน้าจัดทีมแสดงว่าใครผ่าน Peer (✓) / ยังไม่ผ่าน / ไม่อยู่ในทะเบียน · คณะในทะเบียนใช้กันผลประโยชน์ทับซ้อน
- ข้อมูลส่วนบุคคล (อีเมล/โทรศัพท์) เห็นเฉพาะหัวหน้าผู้ตรวจและผู้ดูแลระบบ · ลบออกจากทะเบียนได้

## รายงาน
- **PDF**: ปุ่ม “Report (PDF)” เปิดรายงาน A4 → “ดาวน์โหลด PDF / พิมพ์” → เลือก “บันทึกเป็น PDF” (ใช้ได้ทั้ง iPad/มือถือ/คอมพิวเตอร์)
- **Word (.docx)**: สร้างพร้อมกันเมื่อกด “สร้าง Report” สำหรับแก้ไขต่อ (เก็บใน Supabase Storage)
- ข้อ 2 คะแนนมีเครื่องหมาย `*` ทุกข้อ (ตามคู่มือการประเมินฯ)

## ความปลอดภัยและข้อมูล
- ข้อมูลใช้ภายใน มน. ไม่มีการส่งออกไปยังระบบภายนอก
- ไฟล์รูปหลักฐานอยู่ใน bucket แบบ private — ดาวน์โหลดผ่านแอปซึ่งตรวจสิทธิ์ก่อน (ห้องปฏิบัติการเห็นเฉพาะห้องของตน)
- ทุกการเปลี่ยนคะแนน/ข้อค้นพบ/สถานะถูกบันทึกในประวัติการแก้ไข (audit trail)
- ป้องกัน CSRF ทุกฟอร์ม/คำขอ, cookie แบบ HttpOnly/Secure
- ควรกำหนดนโยบายระยะเวลาเก็บรูปและหลีกเลี่ยงการถ่ายใบหน้าบุคคล (PDPA)
